# bmo-theater

プラットフォームの動画ストアを 1 つのサービスとして提供します。エピソードからなるタイトルを扱い、その元になるのは、
成果物として自身のファイルルートに登録された動画と、すでにディスク上にある動画ファイルのライブラリ(その場で
インデックス化)です。各エピソードは HTTP の Range リクエストでファイルのままストリーミングし、字幕は WebVTT に変換して、
求めに応じて映像に焼き込みます。さらに、プレイリスト、視聴者ごとの再生位置と次に見るもの、サインインなしで動画を開ける
共有リンク、社内の特定アカウントに動画を開放する権限付与を備えます。これらはすべて、各アカウント自身の領域と組織の領域と
いう互いに分離された 2 つの領域に保持されます。また、サイドバーの項目の下でそれらを表示するコンソールバンドルも含みます。
`docs/design.md` はこのサービスが何であるかを、`docs/api.md` はその境界、つまりすべてのルート、発行するイベント、
配置するツール、実行するコマンド、設定を記しています。

## テスト

`cargo test`(testbed 経由)は、クレート唯一のハーネスである `tests/main.rs` を実行します。各テストは、スイートのサーバー上
にある専用の PostgreSQL データベースと専用のファイルルートを使います。対象は次のとおりです。ファイル名からの番号の読み取り
(`names.rs`)、字幕形式の変換(`subtitles.rs`)、Range 応答(`range.rs`)、進捗と次のエピソード(`progress.rs`)、
ffmpeg で作るごく小さな動画を使ったライブラリの計画・スキャン・ストリーミング・再スキャン・焼き込みと、アップロードおよび
パス指定による動画の登録(`scan.rs`、ffmpeg が未インストールの環境ではスキップ)、領域とガード、プレイリストと再生位置
(`realms.rs`)、タイトル一覧の並び順(`orders.rs`)、続きを見ると次のエピソード(`watching.rs`)、作品の名前変更・移動・
削除(`work.rs`)、共有リンク(`shares.rs`)、権限付与(`grants.rs`)、コンソール画面(`console.rs`)、OpenAPI
ドキュメント(`openapi.rs`)、リポジトリ自身のチェック(`repository.rs`)。ツールのクレートは、theater サービスの
スタンドインを相手にする独自のハーネス `tools/theater/tests/main.rs` を持ちます。コンソールバンドルのテストは
`client/tests/` にあり、Bun 製のサービスのスタンドインを相手に `bun run check` で実行されます。

## 構成

| フォルダ | 内容 |
|---|---|
| `src/` | サービスとそのコマンド: ルート、テーブルとそのマイグレーション、スキャン、焼き込み、字幕コンバーター、Range 配信、コンソール画面の接続、OpenAPI ドキュメント |
| `tools/` | デプロイ時にツールホストへ配置される theater ツール: クレート、マニフェスト、入力スキーマ、マニュアル |
| `client/` | コンソールプラグインバンドル。独立したプロジェクトです |
| `deploy/` | サービスのユーザーユニット |
| `docs/` | サービスが何であるかとその境界を定める正典ドキュメント、および OpenAPI ドキュメント |
| `tests/` | クレート唯一のテストハーネスと、各モジュールが共有するもの |

ルートには、Cargo マニフェスト、`Cargo.lock`、`testbed.toml`、`install.toml`（新しいマシンにユニットをインストールするのに必要なもの）、`rustfmt.toml`、`settings.toml`(バイナリに組み込まれる
既定値)、`CLAUDE.md`、`PERSONAL-DATA.md`、`LICENSE`、そしてこの README とその韓国語・日本語・中国語訳があります。

## コマンド

- `bmo-theater serve` はデータベースを現在のスキーマに合わせ、停止を指示されるまでルートに応答します。
- `bmo-theater migrate` はデータベースを現在のスキーマに合わせて終了します。
- `bmo-theater health` は、設定で指定されたサービスが ready と応答すれば 0 で終了します。
- `bmo-theater openapi` は、`docs/openapi.json` に保存されている OpenAPI ドキュメントを出力します。
- `bmo-theater console-reach` は、コンソールがサービスに到達する方法を 1 つの JSON オブジェクトとして出力します。
  デプロイ時のコンソール疎通確認に使われます。
- `bmo-theater tool-env` は、ツールがサービスを見つけるためのデータルートの `env/theater.env` を書き出します。

設定は、バイナリ組み込みの `settings.toml`、次にリリースの隣に置かれたデプロイの `settings.toml` と `settings.local.toml`
(データルートの `env/theater.toml`)、最後に環境変数 `BMO_THEATER_<TABLE>__<KEY>` の順に読み込まれます(`docs/api.md`、
「Settings」)。
